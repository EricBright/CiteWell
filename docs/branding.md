# Branding surfaces

Where the name, icons, and installer identity actually live. Every path here was verified against
this tree at upstream `864b2d47e`; if one has moved, fix this table rather than trusting memory.

## Product name and text

| Surface | File | Current value |
|---|---|---|
| Short name (window title, most UI) | [app/assets/branding/locale/brand.dtd](../app/assets/branding/locale/brand.dtd) | `brandShortName = "Zotero"` |
| Short / full / shorter name | [app/assets/branding/locale/brand.properties](../app/assets/branding/locale/brand.properties) | all `Zotero` |
| Fluent brand strings and trademark line | [app/assets/branding/locale/brand.ftl](../app/assets/branding/locale/brand.ftl) | `-brand-short-name`, `trademarkInfo`, and 6 more |
| Package name and application id | [app/config.sh](../app/config.sh) | `APP_NAME="Zotero"`, `APP_ID="zotero@zotero.org"` |
| Linux desktop entry | [app/linux/zotero.desktop](../app/linux/zotero.desktop) | `Name=Zotero`, `Icon=zotero.ico` |
| Windows installer | [app/win/installer/branding.nsi](../app/win/installer/branding.nsi) | product strings |
| macOS bundle | `app/mac/Contents` | `Info.plist` display name |

The window title does not hard-code the name: [zoteroPane.xhtml](../chrome/content/zotero/zoteroPane.xhtml)
uses `title="&brandShortName;"`, resolved through the branding files above by
[xpcom/intl.js](../chrome/content/zotero/xpcom/intl.js). Change the brand files, not the window.

`APP_NAME` and `APP_ID` are packaging identity, not display text: `APP_ID` also matches add-on
installation and sync identity, so read [naming.md](naming.md) before touching either.

## Icons

| Set | Location | Format |
|---|---|---|
| Application icons (Linux) | [app/linux/icons/](../app/linux/icons) | 32/64/128 PNG plus `symbolic.svg` |
| Application icons (Windows, macOS) | `app/win/`, `app/mac/Contents` | `.ico`, `.icns` |
| In-app icons | [chrome/skin/default/zotero/](../chrome/skin/default/zotero) | PNG and SVG, with `@2x` variants and `8/`, `16/`, `20/` subdirectories |
| Toolbar Z mark | [chrome/content/zotero-platform/](../chrome/content/zotero-platform) | `zotero-z-{16,32}px-australis.png` per platform |
| Toolbar Z source SVG | `chrome/skin/default/zotero/zotero-z-32px-australis-{mac,unix,win}.svg` | regenerated by [scripts/make-z-icons](../scripts/make-z-icons) |

Toolbar PNGs are generated, not hand-edited. Change the SVG and re-run `scripts/make-z-icons`,
otherwise the next regeneration silently reverts your edit.

## User-visible strings that say "Zotero"

| File | Count at this base |
|---|---|
| [chrome/locale/en-US/zotero/zotero.ftl](../chrome/locale/en-US/zotero/zotero.ftl) | 4 |
| `chrome/locale/en-US/zotero/about.dtd` and neighbouring locale files | varies |

Other languages carry the same strings. A full sweep across `chrome/locale/*` is an enormous
diff that conflicts on every merge; prefer adding an override layer, and decide the approach in
roadmap item R7 before editing any of them.

## Update channel

The build reports `app.update.channel = "source"`. A fork must not check Zotero's update servers,
so either keep the source channel (no updates) or remove the update UI — decide in R8. Do not
point the updater at `download.zotero.org`.

## After changing anything here

```bash
npm run build                    # assets are copied during the build
app/scripts/build_and_run -n     # relaunch the staged app
```

Then check: window title, About panel, desktop entry, launcher icon, toolbar at 1x and 2x, and
contrast in both light and dark themes. Skin assets are not hot-reloaded; a stale icon usually
means the build did not run.
