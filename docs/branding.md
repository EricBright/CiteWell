# Branding surfaces

Where the name, icons, and installer identity actually live. Every path here was verified against
this tree at upstream `864b2d47e`; if one has moved, fix this table rather than trusting memory.

## Product name and text

| Surface | File | Current value |
|---|---|---|
| Short name (window title, most UI) | [app/assets/branding/locale/brand.dtd](../app/assets/branding/locale/brand.dtd) | `brandShortName = "Zotero"` |
| Short / full / shorter name | [app/assets/branding/locale/brand.properties](../app/assets/branding/locale/brand.properties) | all `Zotero` |
| Fluent brand strings and trademark line | [app/assets/branding/locale/brand.ftl](../app/assets/branding/locale/brand.ftl) | `-brand-short-name`, `trademarkInfo`, and 6 more |
| Package name and application id | [app/config.sh](../app/config.sh) | `APP_NAME="Zotero"`, `APP_ID="zotero@zotero.org"` |
| Window class / Wayland app id | [app/assets/application.ini](../app/assets/application.ini) | `RemotingName=CiteWell` (the `[App] Name` stays `Zotero` so the profile path does not move) |
| Linux desktop entry | [app/linux/zotero.desktop](../app/linux/zotero.desktop), [packaging/citewell.desktop](../packaging/citewell.desktop) | `Name=CiteWell`, `StartupWMClass=CiteWell` |
| Windows installer | [app/win/installer/branding.nsi](../app/win/installer/branding.nsi) | product strings |
| macOS bundle | `app/mac/Contents` | `Info.plist` display name |

The window title does not hard-code the name: [zoteroPane.xhtml](../chrome/content/zotero/zoteroPane.xhtml)
uses `title="&brandShortName;"`, resolved through the branding files above by
[xpcom/intl.js](../chrome/content/zotero/xpcom/intl.js). Change the brand files, not the window.

`APP_NAME` and `APP_ID` are packaging identity, not display text: `APP_ID` also matches add-on
installation and sync identity, so read [naming.md](naming.md) before touching either.

The About dialog states the fork relationship in `about.xhtml` as code, not as a
localized string: every locale's `about.createdBy` claimed CiteWell was "a project of"
Digital Scholar, which is false and trademark-sensitive. Those strings are now unused by
the dialog, and the sentence is intentionally not translated.

## Launcher and taskbar icon

On KDE Plasma the taskbar icon comes from the desktop entry, not from the window:
[packaging/citewell.desktop](../packaging/citewell.desktop) sets `Icon=citewell`, and AppImage
integration extracts [packaging/citewell.png](../packaging/citewell.png) into the user's icon
directory. The window also carries `app/linux/icons/icon128.png` for compositors that read the
window icon directly.

To change the mark:

1. Replace [app/linux/icons/citewell.svg](../app/linux/icons/citewell.svg). Keep a transparent
   background and a square `viewBox`; do not edit the PNGs, the next run overwrites them.
2. Run `./scripts/make-app-icons`. It writes `icon32.png`, `icon64.png`, `icon128.png`,
   `packaging/citewell.png`, and copies the master over the About dialog's SVG.
3. Rebuild the AppImage ([packaging.md](packaging.md)) and re-integrate it. If integration
   cached the icon, replace that cached copy too, or Plasma keeps showing the old one.

`app/linux/set_launcher_icon` also points a loose desktop entry at `icons/icon128.png`, so that
file must exist at all three sizes. The toolbar quill is a separate monochrome mark: changing the
master does not touch it.

## Rasterising the SVGs

ImageMagick in this environment has no SVG delegate: it silently mis-renders viewBoxes
(negative origins get clipped, `context-fill` renders blank). Generate PNGs with librsvg
instead:

```python
import gi; gi.require_version("Rsvg", "2.0")
from gi.repository import Rsvg
import cairo
h = Rsvg.Handle.new_from_file("chrome/skin/default/zotero/zotero.svg")
s = cairo.ImageSurface(cairo.FORMAT_ARGB32, 2048, 2048)
c = cairo.Context(s); c.scale(2048/980.0, 2048/980.0); h.render_cairo(c)
s.write_to_png("mark-2048.png")
```

Then trim to content, pad, and resize to exact square sizes — launcher icons must be
square (32, 64, 128). `icotool` writes uncompressed BMP frames only, which made a
372 KB `.ico`; the committed icon uses PNG-compressed frames (28 KB), supported by
Windows Vista and later.

## Update channel

The build reports `app.update.channel = "source"`, `app/assets/application.ini` carries **no**
`[AppUpdate] URL`, and `app.update.auto` is off. A check therefore fails locally as "Update URL
not available" and contacts no server. The Check for Updates command states that CiteWell has no
in-app channel yet and offers the repository's releases page; it never opens the inherited
Mozilla wizard. See [packaging.md](packaging.md#updates) for the self-update plan. Do not point
the updater at `download.zotero.org`.

## After changing anything here

```bash
./scripts/make-app-icons         # only when app/linux/icons/citewell.svg changed
cargo run --manifest-path tools/Cargo.toml -p xtask -- build  # assets are copied
app/scripts/build_and_run -n     # relaunch the staged app
```

Then check: window title, About panel, desktop entry, launcher icon, toolbar at 1x and 2x, and
contrast in both light and dark themes. Skin assets are not hot-reloaded; a stale icon usually
means the build did not run.
